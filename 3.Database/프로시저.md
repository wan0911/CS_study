- 정의
    - 여러 개의 쿼리를 하나의 함수처럼 실행하기 위한 퀴리의 집합
    - 장점
        
        ---
        
        1. 성능
            
            : 처음 컴파일된 실행 계획이 DB 서버에 캐시로 남아 있음 → 이후 실행부턴 파싱/최적화 단계를 거치지 않음
            
        2. 트래픽 감소
        : SQL문 전체가 아닌 프로시저명과 파라미터만 전달하면 됨
        : 여러 쿼리를 하나로 묶기 때문에 네트워크 왕복 횟수 감소
            
            → 트래픽 감소
            
        3. 재사용성/유지보수
            
            : 여러 애플리케이션·서비스에서 동일한 프로시저를 공통으로 호출해서 쓸 수 있음
            : 로직 변경 시, 프로시저만 수정하면 됨
            
        4. 보안
            
            : 사용자에게 테이블 직접 접근 권한을 주지 않고, 프로시저 실행 권한만 부여할 수 있음
            
    - 단점
        
        ---
        
        1. 호환성
            
            : DB 회사마다 프로시저 문법이 달라 재사용성이 떨어짐
            
        2. 성능
            
            : 로직이 DB 서버 안으로 집중되기 때문에 호출이 몰리면 DB 서버 자체에 부하가 집중됨.
            
        3. 디버깅
            
            : 쿼리 단계별 디버깅이 어려움
