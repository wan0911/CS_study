- 정의
    - Index란? 왜 필요한지?
        
        : 데이터베이스 테이블의 검색 속도를 향상시키기 위한 자료구조
        : 책의 색인(목차)과 같은 기능을 수행
        : 자주 조회하는 컬럼을 기준으로 데이터를 미리 정렬하여, Full Scan 대신 Index로 원하는 데이터에 빠르게 접근
        
    1. **클러스터드 인덱스 (Clustered Index)**
        
        : 인덱스 순서 자체가 실제 데이터 저장 순서와 일치. 
        : 테이블당 **1개만** 생성 가능 
        : 보통 PK(기본키)에 자동 생성됨
        
    2. **넌클러스터드 인덱스 (Non-Clustered Index)**
        
        : 실제 데이터는 그대로 두고, 별도의 인덱스 페이지에 "정렬된 키값 + 실제 데이터 위치(포인터)"만 저장.
        : 테이블당 **여러 개** 생성 가능
        : 인덱스 위치 → 실제 데이터 순(조회 2번)으로 접근해야 하기 때문에 클러스터드보다 조회 속도가 느릴 수 있음


- 질문
    - Index를 어느 column에 사용하는 것이 좋은지?
        
        : WHERE·JOIN 조건에 자주 사용되고, 중복값이 적고 Unique한 컬럼에 거는 것이 좋음
        
    - 클러스터드 인덱스 vs 넌클러스터드 인덱스
        
        : 클러스터드는 데이터 자체가 정렬된 채로 저장됨
        : 넌클러스터드는 원본 데이터와 별도로 Index별로 정렬된 데이터(키값+위치정보)가 따로 저장됨
        : 한 테이블당 클러스터드 인덱스는 1개만 생성 가능, 넌클러스터드는 여러개 생성 가능
        : 넌클러스터드는 2단계 데이터 조회를 하기 때문에 속도가 느릴 수 있음
